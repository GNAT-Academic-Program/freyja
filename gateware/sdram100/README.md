# SDRAM profile: 100 MHz, CL3

Implementation contract for U32 (W9825G6KH-6) on the routed board at commit
`8cbbd79`. It is worst-case analysis: nothing here has been measured on hardware.
`ref/freya.xdc`, `tools/alloc.py` and `gateware/gate/` do not read this directory,
and the allocation gate is unchanged. This is a timing fixture, not a controller.

## What a design must do

| Item | Requirement |
|---|---|
| Registers | Every address, command, DQM, write-data, tristate and read-capture flop in the IOB, all on `c0`. `run.tcl` fails unless 54 OLOGIC and 16 ILOGIC flops are placed. |
| Forwarded clock | `SDRAM_CLK` from an ODDR (D1 = 1, D2 = 0) on a second output of the same MMCM at **`CLKOUT1_PHASE` 270**. See `top.v`. The generated clock in the XDC derives from that netlist pin, so the phase exists only if the RTL makes it; editing a waveform does not. |
| Read capture | IOB flop samples on `c0` every cycle. The read-latency counter accepts **c0 edge 4 after the edge launching READ** (CL + 1) for the first word, then one word per edge. |
| Drive | Bus 8 mA slow. `SDRAM_CLK` 12 mA fast (already in `ref/freya.xdc`) through R151. |
| Constraints | `sdram100_timing.xdc`, generated by `mkprofile.py`. It refers to `fwd/C` and `dq_i_reg[*]`; a design with other cell names must change those two lines and nothing else. |
| Read to write | BL4 READ on c0 edge 0: FPGA drives no earlier than c0 edge 8, one edge after the last accepted word. Edge 7 overlaps U32 by up to 3.22 ns; edge 8 clears it by 6.78 ns (at the FPGA pad). Generally: never on the edge accepting the last word. A READ interrupted by a WRITE also needs DQM, datasheet section 7.8. |
| Write to read | Release the FPGA drivers no earlier than the c0 edge after the last write word, and no later than one cycle after READ. That leaves at least 17.31 ns before U32 can drive, satisfying section 7.10's clear cycle; two cycles after leaves 7.31 ns and does not. |

Limits above 100 MHz do not apply; rerun. After rerouting any SDRAM net, rerun
`flight.py` too; delay limits do not convert from length.

## Edge table, four-word read

c0 edge *n* is at 10*n* ns. U32 edge T*n* is `sdram_clk` rising at 10*n* + 7.5 ns.
READ is launched at c0 edge 0 and sampled at T0. With CL3, section 10.2 launches
word *k* at T(2 + *k*): valid by tAC after that edge, held until tOH after the next.

| Word | Launched by U32 | Accepted at c0 | Setup relation | Next word launched | Hold relation |
|---|---|---|---|---|---|
| 0 | T2, 27.5 ns | edge 4, 40 ns | 12.5 ns | T3, 37.5 ns | 2.5 ns |
| 1 | T3, 37.5 ns | edge 5, 50 ns | 12.5 ns | T4, 47.5 ns | 2.5 ns |
| 2 | T4, 47.5 ns | edge 6, 60 ns | 12.5 ns | T5, 57.5 ns | 2.5 ns |
| 3 | T5, 57.5 ns | edge 7, 70 ns | 12.5 ns | none: T6, 67.5 ns, ends it, tOH then tHZ | 2.5 ns |

Vivado folds this onto one period. Read from the routed design (`results/edges.txt`):

| Check | Launch | Capture | Requirement | Worst slack, Slow | Worst slack, Fast |
|---|---|---|---|---:|---:|
| Read setup | `sdram_clk` 7.5 | `c0` 20 | 12.5 | **+1.301** (DQ8) | +3.792 |
| Read hold | `sdram_clk` 7.5 | `c0` 10 | 2.5 | +4.476 | **+1.776** (DQ2) |
| Command setup | `c0` 0 | `sdram_clk` 7.5 | 7.5 | +2.735 | **+2.699** (A7) |
| Command hold | `c0` 10 | `sdram_clk` 7.5 | −2.5 | +1.655 | **+1.436** (LDQM) |

The setup row is word *k*'s launch against word *k*'s accept edge (7.5→20 is 27.5→40
shifted two periods). The hold row is the *next* word's launch against that same accept
edge (7.5→10 is 37.5→40 shifted three periods). So STA checks setup against the intended
word and hold against the next word, for every word in the burst, and each capture gets
the intended word.

**The exception:** `set_multicycle_path -setup 2` with no `-hold`, justified by the physics
above: the flop samples every edge and the counter accepts one of them. Read data changes every
cycle, so the hold check Vivado derives is the real one. Each alternative was tested on the
routed design:

| Constraint | Setup, launch → capture, slack | Hold, launch → capture, slack | Meaning |
|---|---|---|---|
| **`-setup 2`** | 7.5 → 20, +1.301 | 7.5 → 10, +1.776 | Correct. |
| None | 7.5 → 10, **−8.699** | 7.5 → 0, +11.776 | Default edge is one too early: word not yet valid. |
| `-setup 2 -hold 1` | 7.5 → 20, +1.301 | 17.5 → 10, +11.776 | Setup unchanged; the hold check moves a whole word away and checks nothing real. |
| `-setup 3` | 7.5 → 30, +11.301 | 7.5 → 20, **−8.224** | One edge late captures the next word. |

Exactly one c0 edge works. **Scope:** 16 paths, 16 endpoints, all `dq_i_reg[*]/D`, starting
at the 16 DQ ports. No pad-loopback path from `c0` reaches those flops. The review fixture used
a clock-to-clock exception; the profile scopes it to `dq_i_reg[*]`, so a design that reads DQ
anywhere else stays at one cycle and fails visibly. Slacks are unchanged by the scoping.

## Results

Worst of the Slow and Fast corners, `xc7a100tfgg676-2`, Vivado 2026.1, ns. `check_timing`
reports only `SDRAM_CLK` without an output delay, which is correct for a forwarded clock.
"Settle" and "leave" are per-net flight times from the IBIS simulation to the last and first
crossings of a valid input level (VIH 2.0 V, VIL 0.8 V), stricter than the datasheet's 1.4 V.
Note 8 adds `(tr + tf)/2 − 1` to setup and hold for slow edges, up to 1.12 ns here.

| Group | Setup | Hold | Limit | Now |
|---|---:|---:|---|---|
| A, BA, command, CKE, DQM | +2.70 (A7) | +1.44 (LDQM) | settle − clock ≤ +4.22; leave − clock ≥ −1.77 | +1.58; −0.36 |
| Same, note 8 in full | +1.57 (A7) | +0.79 (A7) | | |
| Write DQ | +3.08 (DQ8) | +1.41 (DQ2) | settle − clock ≤ +4.26; leave − clock ≥ −1.77 | +1.20; −0.39 |
| Same, note 8 in full | +2.42 (DQ8) | +0.92 (DQ8) | | |
| Read DQ | +1.30 (DQ8) | +1.78 (DQ2) | clock + DQ board delay ≤ 2.17 | 0.60–0.89 |
| Tristate arcs | +3.03 (DQ8) | +0.059 (DQ0) | | |

The +0.059 ns is the thinnest figure. It is release on the c0 edge after the last write word,
counted as if the line changed at release, though it actually floats. Do not release earlier.

## Assumptions and what is not established

- **Jitter:** X4 (C717684) has no datasheet in the repository; 200 ps peak to peak is an
  assumption. It enters clock uncertainty, 0.208 ns: 0.071 system, 0.162 discrete jitter,
  0.120 MMCM phase error. Replace `set_input_jitter` when the part's figure is known.
- **U32 model:** none available. Read delays carry a ±0.3 ns allowance for U32 driving the real
  line instead of its 30 pF test load, and for the 1.65 V against 1.4 V threshold.
- **Read SI:** the flight simulation covers FPGA to U32 only. Ringing and settling of U32 driving
  DQ toward the FPGA are not simulated. U32 input clamps are not modelled, so overshoot figures
  are upper estimates. Crosstalk and simultaneous-switching noise are not assessed.
- **Temperature:** the -6 grade is rated 0–70 °C ambient; the FPGA is industrial grade. The
  profile does not extend U32's rating, and `T_AC`/`T_OH` are 0–70 °C figures.
- **Hardware:** none of this has been measured.

## Reproduce

```sh
source /tools/Xilinx/2026.1/Vivado/settings64.sh
python3 gateware/sdram100/mkprofile.py                     # top.v, *.xdc
vivado -mode batch -nojournal -nolog -source gateware/sdram100/run.tcl
vivado -mode batch -nojournal -nolog -source gateware/sdram100/edges.tcl
python3 gateware/sdram100/margins.py                       # results/
```

Run Vivado from a scratch directory: it leaves `.Xil/` and `clockInfo.txt` there. Products
go to `build/` (ignored), including a 240 KB `routed.dcp`. `results/` holds the small reports
quoted above.

To regenerate the inputs, which needs KiCad's pcbnew and takes about five minutes:

```sh
git show 8cbbd79:kicad/odin.kicad_pcb > /tmp/b.kicad_pcb
DRIVE=8 python3 gateware/sdram100/flight.py /tmp/b.kicad_pcb gateware/sdram100/data/flight_8.json
python3 gateware/sdram100/fieldsolve.py                    # layer impedance and delay
```

Checked 2026-11-03: `flight.py` reproduces `data/flight_8.json` exactly; the XDC's 108 delay
lines match the review fixture; every command and read slack matches it to the picosecond.
